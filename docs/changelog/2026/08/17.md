# 2026-08-17

## Feature — model memory as a knowledge graph (release v0.4.0)

### Summary
Re-modelled BrainMemory from a flat list of notes into a small **knowledge
graph**, while deliberately keeping the tool vocabulary "memory"-oriented (no
"entity" wording). Recall is now *precise*: the server can walk connections
(multi-hop) and explain how two memories relate (shortest path), instead of only
matching words. Still 100% **SQLite / stdlib** — no new dependencies.

### Data model
`src/brainmemory_mcp/memory.py`:
- `memories` — unchanged columns; remains the graph **node**. Existing rows are
  preserved as-is (backward compatible).
- `memory_details` **(new)** — extra facts/observations attached to a memory
  (`ON DELETE CASCADE`).
- `memory_links` **(new)** — directed connection `source_id -> target_id` with
  `relation` (default `related_to`) and `weight`; `UNIQUE(source, target,
  relation)`; both endpoints `ON DELETE CASCADE`.
- Added indexes for details/links.

### Backup + migration (safe, automatic)
- On opening a **pre-graph** database (has `memories` but no `memory_links`),
  the store first snapshots it via SQLite's online backup API to
  `~/.brainmemory-mcp/backups/memory-<UTC timestamp>.db`, **then** adds the new
  tables. Nothing is dropped or rewritten.
- Verified locally against the real DB: backup written to
  `backups/memory-20260817T141028Z.db`; all **131** memories preserved; new
  tables present; graph ops (`link`, `add_detail`, `recall_related`,
  `connect_memories`, `memory_map`) exercised and temporary test artifacts
  cleaned up (final links=0, details=0).

### New `MemoryStore` API
- Details: `add_detail`, `list_details`, `delete_detail`.
- Links: `link`, `unlink`, `links_of`.
- Graph algorithms (plain SQL + Python BFS, data is small):
  - `recall_related(memory_id, depth, relation?, limit)` — undirected multi-hop
    neighbourhood (nodes + links + per-node distance).
  - `connect_memories(source, target, max_depth)` — shortest path (BFS) with the
    chain of memories and links.
  - `memory_map(memory_id?, depth, limit)` — nodes + links map (neighbourhood or
    whole graph).
- `stats()` extended with `total_details`, `total_links`, `relation_types`,
  degree-centrality `most_connected`, and `last_backup`.
- `search()` now also matches text inside attached details.
- `forget()`/`clear()` documented as cascading to details + links.
