# 2026-08-17

## Feature — model memory as a knowledge graph (release v0.4.0)

### Summary
Re-modelled BrainMemory from a flat list of notes into a small **knowledge
graph**, while deliberately keeping the tool vocabulary "memory"-oriented (no
"entity" wording). Recall is now *precise*: the server can walk connections
(multi-hop) and explain how two memories relate (shortest path), instead of only
matching words. Still 100% **SQLite / stdlib** — no new dependencies.

### Data model
`src/brainmemory_mcp/memory.py`:
- `memories` — unchanged columns; remains the graph **node**. Existing rows are
  preserved as-is (backward compatible).
- `memory_details` **(new)** — extra facts/observations attached to a memory
  (`ON DELETE CASCADE`).
- `memory_links` **(new)** — directed connection `source_id -> target_id` with
  `relation` (default `related_to`) and `weight`; `UNIQUE(source, target,
  relation)`; both endpoints `ON DELETE CASCADE`.
- Added indexes for details/links.

### Backup + migration (safe, automatic)
- On opening a **pre-graph** database (has `memories` but no `memory_links`),
  the store first snapshots it via SQLite's online backup API to
  `~/.brainmemory-mcp/backups/memory-<UTC timestamp>.db`, **then** adds the new
  tables. Nothing is dropped or rewritten.
- Verified locally against the real DB: backup written to
  `backups/memory-20260817T141028Z.db`; all **131** memories preserved; new
  tables present; graph ops (`link`, `add_detail`, `recall_related`,
  `connect_memories`, `memory_map`) exercised and temporary test artifacts
  cleaned up (final links=0, details=0).

### New `MemoryStore` API
- Details: `add_detail`, `list_details`, `delete_detail`.
- Links: `link`, `unlink`, `links_of`.
- Graph algorithms (plain SQL + Python BFS, data is small):
  - `recall_related(memory_id, depth, relation?, limit)` — undirected multi-hop
    neighbourhood (nodes + links + per-node distance).
  - `connect_memories(source, target, max_depth)` — shortest path (BFS) with the
    chain of memories and links.
  - `memory_map(memory_id?, depth, limit)` — nodes + links map (neighbourhood or
    whole graph).
- `stats()` extended with `total_details`, `total_links`, `relation_types`,
  degree-centrality `most_connected`, and `last_backup`.
- `search()` now also matches text inside attached details.
- `forget()`/`clear()` documented as cascading to details + links.

### Tools (`src/brainmemory_mcp/server.py`)
- **Kept (same names, richer output):** `store_memory`, `recall_memory`
  (now returns details + connections), `search_memory` (searches details too),
  `list_memories`, `update_memory`, `forget_memory` (cascade),
  `summarize_memories` (graph stats).
- **Added (all "memory"-named, no "entity"):** `add_detail`, `link_memories`,
  `unlink_memories`, `recall_related`, `connect_memories`, `memory_map`.
- **Resources:** kept `brainmemory://stats`; added `brainmemory://graph`.
- Verified: `create_server()` registers **13 tools** + **2 resources**.

### Packaging / docs
- `__version__` `0.3.1 -> 0.4.0`; export `MemoryDetail`, `MemoryLink`.
- README rewritten to document the graph model + the two tool groups.
- NOTE.md updated (Technical Details, API list, Project Layout, Core Flow, ADL,
  Current State, Pending Issues).

### Release

- Published `0.4.0` to PyPI via `twine upload` (API token), then committed +

### Follow-ups

## Feature — search-engine ranking (FTS5/BM25) + graph spreading activation (release v0.5.0)

### Problem
`search_memory` used a single `content LIKE '%query%'`, matching the whole query
as one substring. Multi-word / long queries (e.g. "Burp Firefox sync") returned
**nothing**, so agents had to degrade to single keywords (observed live:
"Burp Firefox sync" → "Burp Suite Firefox proxy" → "Burp" → "Firefox").

### Fix — `src/brainmemory_mcp/memory.py`
- **FTS5 full-text index** `memories_fts(memory_id UNINDEXED, content, tags,
  category, details)` with `tokenize='porter unicode61'`, kept in sync with
  `memories` + `memory_details` via six triggers (insert/update/delete).
- **BM25 ranking** with per-column weights (tags/category weighted higher than
  long content). Query is tokenised (`\w+`, tiny EN/ID stop-word trim); terms are
  joined `OR` (`mode="any"`, default) or `AND` (`mode="all"`) as prefix queries.
- **Blended score** = BM25 text relevance (normalised) + importance + recency.
- **Graph spreading activation**: with `expand=True` (default), BFS from each
  text hit through `memory_links`, adding connected memories with a decayed
  score (`0.5 ** hops`) — so related context surfaces even without the query
  words. Marked `match_type="related"` with `distance`.
- New `search_scored()` returns rich dicts: memory + `relevance` (0..1),
  `match_type` (`text`|`related`|`list`), `matched_terms`, `distance`.
  `search()` kept as a backward-compatible `list[Memory]` wrapper.
- **Fallback**: if the SQLite build lacks FTS5, search uses a tokenised `LIKE`
  term-coverage scorer (log-scaled). `_fts5_available()` detects support at init;
  `stats()` reports the active engine (`fts5-bm25` | `like-fallback`).

### Migration / backup
- `_init_db` now backs up **before any newer-schema upgrade** (missing graph
  tables *or* missing FTS index) via SQLite's online backup API, then adds the
  objects and **backfills** the FTS index from existing rows.
- Verified against the real DB: backup `backups/memory-20260817T142425Z.db`
  written, **131** rows backfilled into `memories_fts`, engine = `fts5-bm25`.

### Tools — `src/brainmemory_mcp/server.py`
- `search_memory` gained `expand: bool = True` and `mode: str = "any"`; returns
  ranked results with the new relevance metadata. Still 13 tools + 2 resources.

### Verification (smoke tests)
- Multi-word EN queries ("ChatGPT guest chat reverse engineering burp
  cloudflare", "RushAutomata pentest queue worker", "php crud mysql") and an
  Indonesian query ("aturan wajib pengembangan proyek") all rank the right
  memories; `mode="all"` narrows correctly.
- Isolated graph test: query "Burp Firefox sync" returns the relevant notes
  ranked, a graph-only memory (no query words) surfaces **only** with
  `expand=True` as `related/distance=1`, and an unrelated memory is excluded.

### Packaging
- `__version__` `0.4.0 -> 0.5.0`. README gained a "Search (like a search engine)"
  section; NOTE.md updated (DB schema, API, ADL, Current State, Pending Issues).

### Release
- Built sdist + wheel (`uv build`), `twine check` passed, published `0.5.0` to
  PyPI via `twine upload`, then committed + pushed to `origin/main`.

### Follow-ups
- Optional semantic layer (embeddings / `similar_to` links) for synonym &
  paraphrase recall — FTS5 covers lexical relevance only.
- Optional: tune ranking weights / expose them; weighted spreading using link
  `weight`.
