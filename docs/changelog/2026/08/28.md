# BrainMemory-MCP Changelog — 2026-08-28

## Release v0.11.8

### Fixed
- `transfer_memories(op="export")` keyset `next_cursor` no longer embeds a raw `\x1f` control byte. It is now base64url-encoded (plain ASCII, URL/JSON-safe) so it round-trips reliably through any MCP client's tool-call serialization — discovered live while running a real local(stdio)->online(HTTP) migration: hand-relaying the previous control-byte cursor was inconsistent (identical-looking input sometimes decoded, sometimes raised `invalid cursor`).
- Cursor decoding now raises the same `invalid cursor` `ValueError` (surfaced as `{"status": "error"}` by the tool) for any malformed/undecodable base64 input, matching the previous validation contract.

### Documentation and tests
- Added `test_export_cursor_is_plain_ascii_and_safely_round_trips` regression test asserting the cursor contains no control/space characters and round-trips correctly.
- Bumped the package version from `0.11.7` to `0.11.8`.

## Release v0.11.7

### Added
- `transfer_memories(op="export")` now supports keyset pagination: new `scope` (`"all"` default, `"memories"`, `"links"`), `limit`, and `cursor` parameters. Each paginated call returns at most `limit` rows ordered by a stable `(created_at, id)` keyset, plus top-level `has_more` / `next_cursor` (also mirrored inside `data.pagination`).
- New SQLite indexes `idx_memories_created_id` and `idx_links_created_id` on `(created_at, id)` so pagination scans stay O(page size) per call instead of degrading with an OFFSET-style scan as the graph grows.

### Changed
- `export_data`/`import_data` payload gained a `scope` field and a `pagination` object (`limit`, `has_more`, `next_cursor`); existing `format`/`format_version`/`counts`/`memories`/`links` fields are unchanged, so old exports/imports keep working unmodified.
- `limit`/`cursor` pagination requires `scope="memories"` or `scope="links"` (a single cursor cannot page two unrelated tables at once); `scope="all"` without `limit` keeps the exact pre-0.11.7 one-shot full-graph export/import behavior.
- `import_data` is unchanged: it already tolerates a partial `memories`/`links` payload and silently skips links whose endpoints don't exist yet (`links_skipped`), which is what makes the memories-then-links two-phase paging flow safe.

### Rationale
- Motivated by a design discussion about migrating a **large** memory graph between two independent `brainmemory-mcp` server processes that share no filesystem (e.g. a local **stdio** instance and a remote **HTTP/SSE** instance) — the prior single-shot inline `data` export could exceed the calling agent's context budget for a "brutal" (very large) graph. Pagination keeps every export/import round-trip bounded in size regardless of total graph size.

### Documentation and tests
- README: documented the paginated migration flow for large graphs (memories-first, then links, looping on `has_more`/`next_cursor`).
- Added `test_export_pagination_pages_through_a_large_graph` (full memories-then-links two-server migration via 2-item pages) and `test_export_pagination_requires_scope_memories_or_links` (validation error for `scope="all"` + `limit`).
- Bumped the package version from `0.11.3` to `0.11.7`.

## Release v0.11.3

### Fixed
- Fixed cross-machine migration over HTTP/SSE: `transfer_memories(op="export")` now returns the full migration object in `data`, which can be passed to `transfer_memories(op="import", data=...)` on another MCP server.
- Removed the incorrect shared-filesystem assumption that caused a remote server to look for a client-local absolute path.

### Compatibility
- Kept optional absolute `output_path` and `input_path` support for server-local file workflows.
- Kept the `backup` operation unchanged.
- Import rejects ambiguous calls that provide both inline `data` and `input_path`.
- No dependencies or MCP tools were added; the surface remains 15 tools.

### Documentation and tests
- Documented MCP download/upload migration and the optional file fallback.
- Added an end-to-end two-server inline export/import test plus file compatibility and validation tests.
- Bumped the package version from `0.11.2` to `0.11.3`.

## Release v0.11.2

### Changed
- Simplified `export_graph_html`: removed the separate `directory` argument and now require one absolute destination `output_path`.
- Changed `transfer_memories` migration export/import from inline payload transfer to UTF-8 JSON files: export requires absolute `output_path`; import requires absolute `input_path`.
- Preserved the existing `backup` operation; only migration export/import changed to an explicit, symmetric file contract.
- Confirmed the tools use the shared FastMCP registration and therefore have identical behavior over stdio and HTTP/SSE.
- Bumped the package version from `0.11.1` to `0.11.2`.

### Security
- File paths reject relative values such as `file.json`, `./file.json`, and `../file.json`.
- Absolute paths containing explicit `.` or `..` segments are also rejected rather than normalized silently.

### Documentation and tests
- Added migration and graph export examples to README.
- Added path validation and JSON portability tests.
