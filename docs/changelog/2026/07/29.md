# 2026-07-29

## Hotfix — pin `mcp<2`, release v0.3.1

### Problem
- Fresh installs of `brainmemory-mcp` began failing at import time:
  ```
  from mcp.server.fastmcp import FastMCP
  ModuleNotFoundError: No module named 'mcp.server.fastmcp'
  ```
- Root cause: the `mcp` (MCP Python SDK) **2.0.0** release removed the
  `mcp.server.fastmcp` module. Our dependency was declared as `mcp>=1.2.0`
  with **no upper bound**, so `uvx brainmemory-mcp` started resolving
  `mcp==2.0.0` automatically — the package worked one day and broke the next
  with no code change on our side.

### Fix
- `pyproject.toml`: pinned the dependency to `mcp>=1.2.0,<2` so installs stay
  on the 1.x line that still ships `mcp.server.fastmcp`.
- Bumped `brainmemory_mcp.__version__` `0.3.0 -> 0.3.1` (PyPI releases are
  immutable; 0.3.0 was already published, so the fix ships as 0.3.1).
- No API/tool/behavior changes — pure dependency-constraint hotfix.

### Release
- Built sdist + wheel, ran `twine check`.
- Git commit + push to `origin/main` (ICWR-TEAM/BrainMemory-MCP) first, then
  published `0.3.1` to PyPI via `twine upload`.

### Follow-ups
- Consider migrating to the `mcp` 2.0 API so the `<2` cap can be lifted.
- Still no automated test suite; a smoke test that imports the server and
  boots stdio would have caught this class of breakage in CI.
