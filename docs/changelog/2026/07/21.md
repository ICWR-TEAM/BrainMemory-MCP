## Dual transport — stdio (default) + web/SSE (`--web`)
- Made the server support two run modes so it works both as a subprocess-based
  MCP server (`uvx brainmemory-mcp`) and as a networked HTTP/SSE server:
  - `server.py` — `run()` now takes `web: bool` (default `False`). When
    `web=False` it runs `server.run(transport="stdio")` and logs to **stderr**
    (stdout is reserved for the MCP protocol); when `web=True` it keeps the SSE
    behavior (logs endpoints to stdout, `transport="sse"`).
  - `__main__.py` — added a `--web` flag (with `BRAINMEMORY_WEB` env fallback:
    `1/true/yes/on`). `--host`/`--port` now documented as web-mode options;
    stdio is the default. Help text points to the `uvx` config.
- Docs: `README.md` reworked to document both modes — a stdio client config
  using `{ "command": "uvx", "args": ["brainmemory-mcp"] }` and the existing
  SSE URL config (now shown under `--web`). Added `--web` / `BRAINMEMORY_WEB`
  to the configuration table.
- Rationale: stdio is the least-friction path for local MCP clients (no port,
  no bind, auto-lifecycle) and matches the requested `uvx` invocation; SSE
  remains available for remote/networked use via `--web`.
- Verified: `python3 -m brainmemory_mcp --help` shows the new `--web` flag and
  mode-specific help; `--version` prints `0.1.0`.

## Release 0.2.0 — fixed `uvx` loading (stdio default) + published to PyPI
- Root cause: PyPI **0.1.0** shipped the SSE-only server, so a stdio MCP client
  running `{ "command": "uvx", "args": ["brainmemory-mcp"] }` got an HTTP/SSE
  server that never spoke the stdio JSON-RPC protocol -> the server "failed to
  load / couldn't be used". Confirmed: `uvx brainmemory-mcp` (0.1.0) produced no
  stdio handshake output.
- Fix: bumped `brainmemory_mcp.__version__` to **0.2.0** (PyPI releases are
  immutable — cannot overwrite 0.1.0) carrying the dual-transport code where
  **stdio is the default** and `--web` selects SSE.
- Build/publish: `uv build` produced sdist + wheel (`0.2.0`); `twine check`
  PASSED for both; `twine upload` (API token, `__token__`) published to
  https://pypi.org/project/brainmemory-mcp/0.2.0/ .
- Verified from PyPI: `uvx --no-cache --refresh brainmemory-mcp --version` ->
  `0.2.0`; full stdio handshake over `uvx brainmemory-mcp` returns `initialize`
  + `tools/list` (7 tools) correctly -> **STDIO WORKS**. PyPI JSON now lists
  releases `['0.1.0', '0.2.0']` with latest `0.2.0`.
- Client config that now works unchanged:
  `"brainmemory": { "command": "uvx", "args": ["brainmemory-mcp"], "type": "stdio" }`.
