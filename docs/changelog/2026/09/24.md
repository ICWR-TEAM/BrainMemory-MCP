# BrainMemory-MCP Changelog — 2026-09-24

## Release v0.13.0

### Added
- Extended the optional `content_chars` content-preview parameter (introduced in
  v0.12.0) to every remaining read/browse tool that returns memory bodies:
  - `recall_memories` — truncates the memory and any included details.
  - `recall_related` — truncates the `root` and every `related` memory.
  - `connect_memories` — truncates every memory on the returned `path`.
  - `memory_map` — truncates every node in `nodes`.
  - `restore_memories` — accepts a per-item `content_chars` on the `list_trash`
    and `history` ops (truncates each embedded `memory`).
- Added `tests/test_content_limit_tools.py` — integration tests that drive the
  registered tools end-to-end and assert truncation + preview flags for each of
  the tools above, plus full-content-by-default behaviour.

### Changed
- Updated docstrings for the affected tools, README (tool table + expanded
  "Preview long content" section), and the `__init__.py` module docstring with
  the v0.13.0 note.
- Bumped package version from `0.12.0` to `0.13.0`.

### Notes
- Reuses the same `server._apply_content_limit` helper and semantics as v0.12.0
  (`content_truncated` / `content_length` flags; full content via
  `recall_memories`).
- Write tools (`store_memories`, `update_memories`), `transfer_memories`, and
  `export_graph_html` are intentionally left full-fidelity so request echoes,
  migrations, and backups are never truncated.
- No breaking changes (all params optional, default = full content). Zero new
  dependencies. 15-tool surface unchanged. See ADL 012 in NOTE.md.

## Release v0.12.0

### Added
- Added an optional `content_chars` parameter to `search_memory` and
  `list_memories` that truncates each returned memory's `content` to a preview
  of that many characters (positive int).
- Truncated memories now carry `content_truncated: true` and `content_length`
  (the original, untruncated character count) so callers know it is a preview
  and can fetch the full text via `recall_memories`.
- Added `server._apply_content_limit(memory_dict, max_chars)` helper that
  performs the presentation-layer truncation (non-mutating).
- Added `tests/test_content_limit.py` covering none/non-positive/short/long
  limits, non-mutation of the source dict, and non-string content handling.

### Changed
- `search_memory` and `list_memories` docstrings document the new parameter and
  preview flags.
- Updated README (tool table + new "Preview long content" section) and
  `brainmemory_mcp/__init__.py` module docstring with the v0.12.0 note.
- Bumped package version from `0.11.9` to `0.12.0`.

### Notes
- No breaking changes: omitting `content_chars` (or passing a non-positive /
  non-int value) returns full content in the exact prior output shape; the two
  extra keys appear only on memories that were actually truncated.
- Truncation happens after ranking/scoring, so search relevance, ordering,
  importance, and recency are computed on full content — only the returned text
  is trimmed.
- The 15-tool surface is unchanged (parameter addition only). Storage, the
  FTS5/BM25 index, and graph expansion are untouched. Zero new dependencies
  (stdlib only). See ADL 011 in NOTE.md.
